# Phase I model identification: event-factor pseudo-replication

The **source-native v4 event-factor panel** contains 233,442 joined event/proposition–Treasury factor research rows, but it covers only 6 calendar event dates and 18 factors. Across the dates there are only 108 distinct (factor ID, calendar date, factor level) combinations. Paired non-null event probability changes and per-proposition-aligned factor changes cover 192,294 rows but at most 5 matched event calendar dates for each Treasury factor. Most of the seeming observations reuse the same daily Treasury rate source outcome, making naively pooled iid t-statistics, OLS standard errors, FDR q-values and precision claims unsuitable for institutional inference.

The research-only producer `lab/phase1_event_pseudoreplication_audit.py` persists an append-only one-row build manifest `lab_event_pseudoreplication_builds_v1` and an 18-factor methodological acceptance screen `lab_event_pseudoreplication_factors_v1`. It compares the distinct paired event days to a **predeclared research-screen threshold of 60 calendar dates**, NOT an assumed effective iid sample size or universal econometric requirement. Sixty dates would only make longer-run exploratory estimates possible; it would not certify causal identification, sufficient power, portfolio-risk covariance, true source PIT, vendor rights or independently reviewed event mappings.

For each factor, the audit reports observed proposition-factor rows, truly distinct calendar dates, dates with non-null paired changes, number of underlying propositions and apparent paired rows per distinct paired calendar day. It rejects source-manifest mismatch, duplicate factor families, impossible counts, changed source contract, invalid units/hashes/source dates, and inappropriate original publication or model approval flags. It never returns a released causal beta: approval fields are hard-coded FALSE, including if the 60-date screen is met.

**Econometric implication:** eventually use event-release-time-matched independent market outcomes, temporal blocked/rolling evaluation, source-known-at timestamps, predeclared event/industry clusters, suitable HAC/cluster/heteroskedastic covariance and independent model risk review. Cross-sectional quote changes for many event propositions on one day do not magically create independent factor shocks. Cluster count cannot be inferred from the 192,294 joined rows; source-provenance-valid temporal replication is required before statistical claims. Current event-channel mapping has no independent signed approval.

No underlying raw factor or event data are changed; no license or historical backtest is authorized. Run as an internal-only MotherDuck Flight, pinned to a 40-character Git SHA.
