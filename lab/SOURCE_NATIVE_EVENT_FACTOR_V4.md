# Phase I v4 — source-native, independently aligned event–factor research

The previous source repair materialized `lab_event_factor_panel_v3_1` by joining existing v2 + v3 to raw factor hashes and runs. That successfully corrected 76,662 source-day/carry labels and 2,806 material/null-versus-valued aligned changes, but it still required historic v2/v3 panels to rebuild.

`lab/phase1_source_native_panel_v4.py` is the independent **source-native successor**. It reads `lab_event_features`, `lab_factor_observations` and the active factor catalog, with explicit aliases for `event_day` and `source_factor_day` to avoid the upstream v3 `SELECT d.observed_date, ..., f.*` shadowing defect. It selects the latest *observed* factor record on or before each event date with the same deterministic revision ordering used by the historic research selection. It computes `previous_aligned_factor_value` with `LAG` **partitioned by proposition_id and factor_id**, rather than factor alone: that matters when a proposition enters or leaves the observed event sample. The previous-aligned date is an observed event day, **not necessarily the preceding financial trading day**. It uses percentage factor levels and basis-point changes without conflating units.

The builder then checks every overlapping key and substantive source/value/previous/change field against the **separately generated and exact-source-verified** `lab_event_factor_panel_v3_1_latest`. A disagreement, an unflagged late factor, an unknown factor family, duplicates, future observed factor dates, invalid source SHA or unapproved release flag fails closed before persistence. Newer observed events may extend beyond the independent v3.1 reference, but must also satisfy local semantic checks. The latest-only `lab_event_factor_panel_v4_latest` view prevents pooling multiple replay builds; append-only `lab_event_factor_panel_v4` and `lab_event_factor_v4_builds_v1` preserve historical execution attestations.

**Important limits:** existing factors are retrospective as downloaded; `source_factor_day` is not verified `first_published_at` and `provider_record_available_at` can refer to an institutional ingestion clock, not the original vintage. The new v4 is an internally consistent research input for further event and risk modeling, **not** a causal event impact, tradable backtest, independently approved beta or commercial reuse entitlement. Never use it to turn data first ingested after the historical event into a historical trading signal.

The v4 build is separate from and does not overwrite v2, v3, v3.1 or raw records. No new public API endpoint, vendor source rights switch, FRED credential, model risk signoff or production authorization is created. Execute with `LAB_RESEARCH_SCOPE=internal-only`, a 40-character `LAB_PIPELINE_COMMIT`, and the explicitly scoped MotherDuck Flight access. The source and acceptance code remain version pinned.
